<Endpoint method={"POST"} path={"/v1/asset-objects/{uid}/complete"} />

Marks an object created with [Create an upload](/api/buckets/create-an-upload) as `ready`
after you have `PUT` its bytes to the presigned `upload_url`. Send no request body.

The file is checked in storage first. If it is not there yet, the call fails with `409`
(`the file has not been uploaded yet; upload it to upload_url before completing`) and the
object stays `pending_upload`, so you can upload and complete again. The object's
`size_bytes` and ETag are then taken from storage, not from the `size_bytes` you sent when
creating the upload.

Completing an object that is already `ready` is safe and returns it unchanged. The storage
allowance is checked again here with the stored size. If completing the upload would take
your account past its free file storage, the call fails with `403` and the uploaded file
is removed from storage; the object stays `pending_upload`.

Requires the `resource write` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Errors

| Status | Meaning |
|---|---|
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | Your role cannot upload, you cannot access the workspace, or completing the upload would exceed your account's free file storage allowance. |
| `404` | The object (or its bucket) does not exist in this workspace. |
| `409` | The object is neither `pending_upload` nor `ready` (`asset upload cannot be completed`), or the file has not reached storage yet. |

Errors use the [standard error format](/api#errors).
