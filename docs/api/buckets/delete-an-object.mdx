<Endpoint method={"DELETE"} path={"/v1/asset-objects/{uid}"} />

Deletes the object from storage and removes it from the bucket's object list. This happens
immediately (it is not an operation) and cannot be undone. Objects still in
`pending_upload` can be deleted too, which cancels the upload.

Requires the `resource write` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The object's `uid` (the `object_id` returned by [Create an upload](/api/buckets/create-an-upload)).

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Response

<ResponseBlock status={"200"}>

The object was deleted.

</ResponseBlock>

<Param name={"success"} type={"boolean"} required>

`true` when the request succeeded.

</Param>

<Param name={"message"} type={"string"} required>

Human-readable status message.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | The object (or its bucket) does not exist in this workspace, or was already deleted. |
| `409` | The object's bucket is being deleted. |

Errors use the [standard error format](/api#errors).
