<Endpoint method={"POST"} path={"/v1/asset-buckets/{uid}/uploads"} />

Starts an upload by reserving an object and returning a presigned URL to send the file to.
No file data goes through this endpoint.

**Upload flow:**

1. Call this endpoint with the file's name, content type and size. The object is created
   with status `pending_upload`.
2. Send the file's bytes with an HTTP `PUT` to `upload_url` (`method` is always `PUT`),
   setting **every header in `headers`** exactly as returned. For public buckets these
   include `x-amz-acl: public-read` and a `Cache-Control` header. The URL expires at
   `expires_at` (10 minutes by default).
3. Call [Complete an upload](/api/buckets/complete-an-upload) with `object_id` to mark the
   object `ready`. Only `ready` objects count towards storage usage and can be read with
   [Create an object read URL](/api/buckets/create-an-object-read-url).

```bash
curl -X PUT "$UPLOAD_URL" \
  -H "Content-Type: application/pdf" \
  -H "x-amz-acl: public-read" \
  -H "Cache-Control: public, max-age=31536000, immutable" \
  --data-binary @report.pdf
```

The object's `key` is generated for you. It is the bucket's key prefix, then `key_prefix`
(if sent), then a slug of the file name with a short unique suffix, for example
`report-d5e6f7.pdf`.

Things to know:

- Allowed content types and extensions: `application/pdf` (`.pdf`), Word `.docx`
  (`application/vnd.openxmlformats-officedocument.wordprocessingml.document`), `image/gif`,
  `image/jpeg` (`.jpg`, `.jpeg`), `image/png`, `image/svg+xml`, `image/webp`, `text/csv`,
  `text/html` (`.html`, `.htm`), `text/markdown` and `text/x-markdown` (`.md`), `text/plain`
  (`.txt`, `.md`, `.csv`), `application/vnd.apple.mpegurl` and `application/x-mpegurl`
  (`.m3u8`), `video/mp2t` (`.ts`), `video/mp4`, `video/quicktime` (`.mov`, `.qt`),
  `video/webm`, `video/x-matroska` (`.mkv`) and `video/x-msvideo` (`.avi`).
- If `filename` has an extension, it must match `content_type`.
- `size_bytes` must be above zero and no larger than the maximum upload size (1 GiB by
  default, shown as `max_upload_bytes` in
  [Get workspace bucket usage](/api/buckets/get-workspace-bucket-usage)).
- The upload is rejected with `403` if it would take your account's file storage past the
  free allowance.
- The bucket must be `ready`.

Requires the `resource write` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Request body

<Param name={"filename"} type={"string"} required>

Original file name. Used for the object's `filename` and to build its key. Its extension must match `content_type`.

</Param>

<Param name={"content_type"} type={"string"} required>

MIME type of the file. Case-insensitive. Must be one of the allowed types listed above.

</Param>

<Param name={"size_bytes"} type={"integer"} required constraints={"min 1"}>

Size of the file in bytes. Must be above zero and within the maximum upload size.

</Param>

<Param name={"key_prefix"} type={"string"} constraints={"max length 512"}>

Optional folder path to place the object in, for example `invoices/2026`.
Leading and trailing slashes are ignored. Each folder name must start with a
letter or number and may contain only letters, numbers, spaces, dots, dashes and
underscores.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `400` | Validation failed. Possible messages: `invalid request` (malformed JSON or a missing required field), `filename is required`, `size_bytes must be greater than zero`, `file exceeds max upload size`, `unsupported file content_type`, `filename extension does not match content_type`, `filename must include a supported file extension`, `folder path is too long (max 512 characters)` and `folder names may only contain letters, numbers, spaces, dots, dashes, and underscores`. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | Your role cannot upload, you cannot access the workspace, or the upload would exceed your account's free file storage allowance. |
| `404` | The bucket does not exist in this workspace. |
| `409` | The bucket is not `ready`. |

Errors use the [standard error format](/api#errors).
