<Endpoint method={"DELETE"} path={"/v1/asset-buckets/{uid}"} />

Queues deletion of the bucket and returns `202 Accepted` with the `operation_id` of the
delete operation. The bucket moves to `deleting` straight away. Poll
[Get an operation](/api/operations/get-an-operation) to follow it.

When the operation succeeds, **every object in the bucket is deleted** and all of the
bucket's access keys are revoked. This cannot be undone. If deletion fails, the bucket's
status becomes `failed` and `last_failure` explains why.

Send `X-Idempotency` to make retries safe. The key is checked before the bucket's state, so
repeating a delete with the same key returns the original operation with `200 OK` and
`is_replay: true` instead of `409` or `404`. Reusing it for a different action or bucket
returns `409` with `action: idempotency_key_reused`.

The returned `bucket` omits `free_storage_bytes` and `max_image_size_bytes`.

Requires the `resource write` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.
