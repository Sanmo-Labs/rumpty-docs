<Endpoint method={"PUT"} path={"/v1/asset-buckets/{uid}/cors"} />

Replaces the browser origins allowed to make cross-origin (CORS) requests to the bucket,
for example so a web app can upload directly to a presigned URL or fetch objects with
`fetch()`. The RumptyCloud console's own origin is always allowed and is not listed.

The list you send replaces the current one. Send an empty array to remove all custom
origins. The change is saved immediately and pushed to storage. If that push fails, a
background sync applies it shortly afterwards.

Rules for each origin:

- Must be `scheme://host[:port]` with `https://` or `http://`, for example
  `https://app.example.com`. Paths, queries, fragments and credentials are rejected.
- `*` allows any site. A leading `*.` wildcard in the host (for example
  `https://*.example.com`) allows subdomains. `*` is not allowed anywhere else in the host.
- At most 255 characters each and at most 20 origins. Blank entries are ignored, and origins
  are lower-cased and de-duplicated.

The bucket must be `ready`. Requires the `resource write` permission (owner, admin or
developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Errors

| Status | Meaning |
|---|---|
| `400` | An origin is invalid, or there are more than 20. Possible messages include `"<origin>" needs https:// (or http://) at the start`, `"<origin>" must start with https:// or http://`, `"<origin>" should be just the scheme, host and port, e.g. https://app.example.com`, `"<origin>" can only use * at the start of the host, e.g. https://*.example.com`, `"<origin>" is too long`, `"<origin>" is not a valid origin, e.g. https://app.example.com`, `a bucket can have at most 20 allowed origins` and `invalid request` (malformed JSON). |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | The bucket does not exist in this workspace. |
| `409` | The bucket is not `ready` yet. |

Errors use the [standard error format](/api#errors).
