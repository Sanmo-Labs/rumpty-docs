<Endpoint method={"GET"} path={"/v1/asset-buckets"} />

Returns the workspace's buckets, newest first. Deleted buckets are not included, but
buckets that are still `provisioning`, `deleting` or `failed` are.

Without query parameters, every bucket is returned in `data`. Send `page` or `page_size` to
paginate. A top-level `pagination` object is then added next to `data`, and `q` filters the
results. `q` is ignored unless `page` or `page_size` is present.

Requires read access to the workspace (any role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Query parameters

<Param name={"page"} type={"integer"} constraints={"min 1"}>

Page number, starting at 1. Values below 1 (or non-numbers) are treated as `1`. Sending this enables pagination.

</Param>

<Param name={"page_size"} type={"integer"} defaultValue={"10"} constraints={"min 1 · max 100"}>

Items per page. Defaults to `10`. Values above `100` are capped at `100`. Sending this enables pagination.

</Param>

<Param name={"q"} type={"string"}>

Case-insensitive substring search across the bucket's name, slug, storage bucket name, status and visibility. Only applied when paginating.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>
