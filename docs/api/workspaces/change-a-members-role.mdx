<Endpoint method={"PATCH"} path={"/v1/workspaces/{workspace_uid}/members/{member_uid}"} />

Changes a member's role to `admin`, `developer` or `viewer`. The new permissions apply to the
member's next request.

Requires the owner or admin role. Some changes are not allowed:

- The owner's role cannot be changed, and no one can be made owner.
- Admins cannot give anyone the `admin` role, and cannot change another admin's role.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"workspace_uid"} type={"string"} required>

The workspace's `uid`. When the route also takes `X-Workspace-Slug`, both must name the same workspace.

</Param>

<Param name={"member_uid"} type={"string"} required>

The membership's `uid` from [List members](/api/workspaces/list-members). This is not the member's `user_uid`.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Request body

<Param name={"role"} type={"string"} required enumValues={["admin","developer","viewer"]}>

The member's new role.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `400` | Validation failed: `role is required` (missing or malformed body) or `role must be admin, developer, or viewer`. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | Not allowed: your role cannot manage members, `the workspace owner role cannot be changed`, `admins cannot assign the admin role`, or `admins cannot change another admin's role`. |
| `404` | No member with this `uid` in the workspace (`workspace member not found`). |

Errors use the [standard error format](/api#errors).
