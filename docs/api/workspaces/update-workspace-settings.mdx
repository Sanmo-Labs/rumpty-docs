<Endpoint method={"PATCH"} path={"/v1/workspaces/{workspace_uid}/settings"} />

Changes the workspace's settings. Omitted fields are left unchanged.

`vm_exec_enabled` controls whether [Run a command on a VM](/api/virtual-machines/run-a-command-on-a-vm)
is allowed in this workspace. It is off by default. AI assistants use that endpoint to run
commands on your VMs.

Requires the owner or admin role.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"workspace_uid"} type={"string"} required>

The workspace's `uid`. When the route also takes `X-Workspace-Slug`, both must name the same workspace.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Request body

<Param name={"vm_exec_enabled"} type={"boolean"}>

Allow running commands on the workspace's VMs through the API.

</Param>
