<Endpoint method={"PATCH"} path={"/v1/workspaces/{workspace_uid}/notifications"} />

Sets or removes the workspace's alert webhook. When set, workspace alerts (for example an app
that keeps crashing) are also sent as an HTTP `POST` to this URL, in addition to email. You
can use a Discord webhook URL or any HTTPS endpoint.

- Send a URL to set or replace the webhook.
- Send `""` to remove it.
- Omit `webhook_url` (or send `null`) to leave it unchanged.

Requires the owner or admin role.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"workspace_uid"} type={"string"} required>

The workspace's `uid`. When the route also takes `X-Workspace-Slug`, both must name the same workspace.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Request body

<Param name={"webhook_url"} type={"string | null"} constraints={"max length 2048"}>

HTTPS URL to post alerts to. Leading and trailing spaces are trimmed. Must use `https` and include a host. Send `""` to remove the webhook.

</Param>

## Response

<ResponseBlock status={"200"}>

The settings were saved.

## Errors

| Status | Meaning |
|---|---|
| `400` | Validation failed: `invalid request` (malformed JSON), `webhook URL must be 2048 characters or less`, `webhook URL is not valid`, or `webhook URL must use https`. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |

Errors use the [standard error format](/api#errors).
