<Endpoint method={"GET"} path={"/v1/git-connections/github-app/repositories"} />

Returns every repository the GitHub App can access across all of the workspace's GitHub
connections. Repositories are grouped by connection, most recently connected first, and a
repository reachable through several connections is listed once.

Results are cached for a few minutes. After you change which repositories the app can access
on GitHub, send `refresh=1` to bypass the cache.

Requires the `secrets read` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Query parameters

<Param name={"refresh"} type={"string"} enumValues={["1","true"]}>

Send `1` or `true` to fetch fresh results from GitHub instead of the cache. Any other value is ignored.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | No GitHub account is connected to this workspace. |
| `500` | GitHub could not be reached or refused the request for one of the connections. |

Errors use the [standard error format](/api#errors).
