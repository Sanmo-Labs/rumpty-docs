<Endpoint method={"DELETE"} path={"/v1/firewall-policies/{uid}/attachments/{attachment_uid}"} />

Removes an attachment, so the policy no longer applies to that resource. A `firewall.apply`
operation is queued for the resource, but its ID is not returned. If no other policy is
attached, the resource is no longer filtered.

Find the attachment's `uid` in `attached_resources` from
[Get a firewall policy](/api/firewall-policies/get-a-firewall-policy).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The firewall policy's `uid`.

</Param>

<Param name={"attachment_uid"} type={"string"} required>

The attachment's `uid`.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Response

<ResponseBlock status={"200"}>

The policy was detached.
