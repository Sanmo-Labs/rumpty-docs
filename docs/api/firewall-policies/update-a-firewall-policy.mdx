<Endpoint method={"PATCH"} path={"/v1/firewall-policies/{uid}"} />

Changes a policy's name, description or default flag. Send only the fields you want to
change. Renaming the policy also changes its `slug`. This does not change any rules, so no
firewall operation is queued.

A name that another policy in the workspace already uses (exact, case-sensitive match) is
rejected with `409`.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The firewall policy's `uid`.

</Param>

## Headers

</Param>

## Request body

<Param name={"name"} type={"string"}>

New name. Leading and trailing spaces are trimmed. Cannot be blank.

</Param>

<Param name={"description"} type={"string"}>

New description. Send an empty string to clear it.

</Param>

<Param name={"is_default"} type={"boolean"}>

Marks or unmarks the policy as a workspace default. This is a label only.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `400` | The body is not valid JSON (`invalid request`) or `name` is blank (`policy name cannot be empty`). |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | No firewall policy with this `uid` exists in the workspace. |
| `409` | Another policy in the workspace already has this name. |

Errors use the [standard error format](/api#errors).
