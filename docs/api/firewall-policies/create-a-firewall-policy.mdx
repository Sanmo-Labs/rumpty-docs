<Endpoint method={"POST"} path={"/v1/firewall-policies"} />

Creates a firewall policy. The policy is not attached to anything yet, so it has no effect
until you [attach it](/api/firewall-policies/attach-a-firewall-policy) to a resource.

Every new policy starts with two default rules, so attaching it does not lock you out:

- TCP port `22` from `0.0.0.0/0` (SSH, needed by `rumpty ssh` and the CLI).
- TCP port `8080` from `0.0.0.0/0` (the default VM app port).

You can update or delete these rules like any other.

Policy names must be unique in the workspace. A name already used by another policy is
rejected with `409`. The check is on the exact name (after trimming spaces) and is
case-sensitive, so `Web servers` and `web servers` can both exist. Names of deleted
policies can be reused.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.
