<Endpoint method={"POST"} path={"/v1/firewall-policies/{uid}/attachments"} />

Attaches the policy to a VM, database or deployment in the workspace and queues a
`firewall.apply` operation for that resource. From then on the resource only accepts
traffic allowed by its attached policies.

Attaching a policy that is already attached to the resource changes nothing. It returns
the existing attachment with `201` and an empty `operation_id`.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

</Param>

| `400` | The body is not valid JSON (`invalid request`) or `resource_type` is not supported (`resource_type must be vm, database, or deployment`). |
