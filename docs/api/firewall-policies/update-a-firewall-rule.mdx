<Endpoint method={"PATCH"} path={"/v1/firewall-policies/{uid}/rules/{rule_uid}"} />

Changes a rule. Send only the fields you want to change. Values are validated the same way
as in [Add a firewall rule](/api/firewall-policies/add-a-firewall-rule), and the policy's
default rules can be changed too.

If you send either port, the range is rebuilt from the ports in this request only: a missing
`port_end` becomes `port_start`, and a missing `port_start` is treated as `0`, which fails
validation. To change a range, send both `port_start` and `port_end`.

A `firewall.apply` operation is queued for every resource the policy is attached to. The
response's `operation_id` is the first of those, or an empty string when the policy is not
attached to anything.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.
