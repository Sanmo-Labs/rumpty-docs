<Endpoint method={"POST"} path={"/v1/firewall-policies/{uid}/rules"} />

Adds an allow rule to the policy and queues a `firewall.apply` operation for every resource
the policy is attached to. The response's `operation_id` is the first of those operations,
or an empty string when the policy is not attached to anything.

Defaults and limits:

- `direction` defaults to `inbound`, `action` to `allow` and `protocol` to `tcp`.
- Leave out both ports (or send `0` for both) to match all ports.
- Send only `port_start` to match a single port.
- `cidr` is required. A single address needs a prefix length, such as `198.51.100.7/32`.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Request body

<Param name={"direction"} type={"string"} defaultValue={"inbound"} enumValues={["inbound","outbound"]}>

Traffic direction the rule applies to. Case-insensitive.

</Param>

<Param name={"action"} type={"string"} defaultValue={"allow"} enumValues={["allow"]}>

What to do with matching traffic. Only `allow` is supported.

</Param>

<Param name={"protocol"} type={"string"} defaultValue={"tcp"} enumValues={["tcp","udp","all"]}>

IP protocol to match. Case-insensitive.

</Param>

<Param name={"port_start"} type={"integer"} constraints={"min 0 · max 65535"}>

First port of the range, from 1 to 65535. `0` together with `port_end` `0` (or both omitted) matches all ports.

</Param>

<Param name={"port_end"} type={"integer"} constraints={"min 0 · max 65535"}>

Last port of the range. Defaults to `port_start`. Must not be lower than `port_start`.

</Param>

<Param name={"cidr"} type={"string"} required>

Source address range in CIDR notation, IPv4 or IPv6. Use `0.0.0.0/0` to allow any IPv4 source.

</Param>

<Param name={"description"} type={"string"}>

Optional note about what the rule is for. Leading and trailing spaces are trimmed.

</Param>
