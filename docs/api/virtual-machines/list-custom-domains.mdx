<Endpoint method={"GET"} path={"/v1/vms/{uid}/domains"} />

Returns the custom domains attached to the VM, with their verification status.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The VM's `uid`.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Response

<ResponseBlock status={"200"}>

The VM's custom domains.

</ResponseBlock>

<Param name={"success"} type={"boolean"} required>

`true` when the request succeeded.

</Param>

<Param name={"message"} type={"string"} required>

Human-readable status message.

</Param>

<Param name={"data"} type={"array of objects"}>

<ParamChildren open label={"item attributes"}>

<Param name={"uid"} type={"string"} required>

Unique identifier of the custom domain.

</Param>

<Param name={"vm_uid"} type={"string"}>

UID of the VM the domain is attached to.

</Param>

<Param name={"vm_app_uid"} type={"string"}>

Deprecated. Same value as `vm_uid` (it holds the VM's UID, not a VM app's). Use `vm_uid`.

</Param>

<Param name={"domain_name"} type={"string"} required>

The custom domain.

</Param>

<Param name={"status"} type={"string"} required enumValues={["pending","verified","active","failed"]}>

`pending` until verified and routed, `active` once traffic is served, `failed` when DNS
verification or routing failed (see `last_error`).

</Param>

<Param name={"verification_txt"} type={"string"} required>

Value to publish in a `TXT` record at `rumpty-challenge.<domain_name>`.

</Param>

<Param name={"last_error"} type={"string"}>

Reason for the last failure. Omitted when there is none.

</Param>

<Param name={"created_at"} type={"string (date-time)"} required>

When the domain was added.

</Param>

</ParamChildren>

</Param>
