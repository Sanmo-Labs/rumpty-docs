<Endpoint method={"DELETE"} path={"/v1/vms/{uid}"} />

Queues deletion of the VM. The VM moves to `deleting` straight away and disappears from
listings once the operation finishes. Snapshots of the VM are kept. Find them with
[List snapshots](/api/snapshots/list-snapshots).

This is asynchronous. It returns `202 Accepted` with an `operation_id`. See
[Get an operation](/api/operations/get-an-operation). Send an `X-Idempotency` key to make
retries safe: a retry with the same key returns the original operation with `200`, even
after the VM has been deleted.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The VM's `uid`.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional unique key for this request, such as a UUID. Leading and trailing spaces are
ignored. If you send a key you already used for the same action on the same resource, the
original operation is returned with `200 OK` and `X-Idempotency-Replay: true`, and nothing
new is queued. The replay check runs before the resource is loaded or its state is
checked, so a retry gets the original result even after the action has finished. Reusing a
key for a different action, resource type or resource returns `409` with
`action: idempotency_key_reused`. Keys are shared across the workspace. Without a key,
every request is treated as new.

</Param>
