<Endpoint method={"POST"} path={"/v1/vms"} />

Queues a new VM and returns `202 Accepted` with the `operation_id` of the create operation.
The VM starts in `provisioning`. Poll [Get an operation](/api/operations/get-an-operation)
or [Get a VM](/api/virtual-machines/get-a-vm) to see when it is `running`.

`X-Idempotency` is optional but recommended. If you repeat a request with the same key and
the same `name`, you get the original operation back with `200 OK` and
`X-Idempotency-Replay: true`, and nothing new is queued. The replay check runs after the
basic field checks (required fields, SSH keys, zone) but before the billing, plan, image,
quota and name checks, so a retry after the VM was created still returns the original
operation.
Reusing the key with a different `name` returns `409` with `action: idempotency_key_reused`.
Without a key, every request queues a new VM.

Things to know:

- You must accept the acceptable use policy before creating your first VM. Until then this
  endpoint returns `428` with `action: accept_acceptable_use_policy`.
- Provide `image_slug`, or `snapshot_uid` to create the VM from a snapshot. A VM created from
  a snapshot uses the snapshot's image and login user and is always persistent.
- New VMs from an image log in as `root`.
- If the plan is ephemeral-eligible, the VM is ephemeral even when `ephemeral` is `false`.
  Ephemeral VMs expire after the plan's `default_runtime_mins` (72 hours if the plan sets
  none). Each account can have one active ephemeral VM.
- Desktop images need a plan with at least 2 vCPU and 2048 MiB of memory.
- The VM gets an HTTPS app URL that forwards to port `8080` by default. Change it with
  [Set the VM app port](/api/virtual-machines/set-the-vm-app-port).
- VM names must be unique in the workspace. Uniqueness is checked on the slug of the name,
  so `Web 1` and `web-1` clash.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional unique key for this request, such as a UUID. Leading and trailing spaces are
ignored. If you send a key you already used for the same action on the same resource, the
original operation is returned with `200 OK` and `X-Idempotency-Replay: true`, and nothing
new is queued. The replay check runs before the resource is loaded or its state is
checked, so a retry gets the original result even after the action has finished. Reusing a
key for a different action, resource type or resource returns `409` with
`action: idempotency_key_reused`. Keys are shared across the workspace. Without a key,
every request is treated as new.

</Param>

## Request body

<Param name={"name"} type={"string"} required>

Display name of the VM. Leading and trailing spaces are trimmed. Its slug must be unique among the workspace's VMs.

</Param>

<Param name={"plan_slug"} type={"string"} required>

Slug of a compute plan from [List plans](/api/virtual-machines/list-plans). Case-insensitive.

</Param>

<Param name={"image_slug"} type={"string"}>

Slug of an image from [List images](/api/virtual-machines/list-images). Required unless `snapshot_uid` is set, and ignored when it is.

</Param>

<Param name={"vpc_slug"} type={"string"} required>

Slug of the VPC to attach the VM to. Use `default` for the platform's default private network.

</Param>

<Param name={"zone_slug"} type={"string"} defaultValue={"olas-closet"}>

Zone to run the VM in. Defaults to `olas-closet`, currently the only zone.

</Param>

<Param name={"ssh_key_uids"} type={"array of strings"} required>

UIDs of SSH keys to install on the VM. At least one is required. Each key must be yours or belong to the workspace.

</Param>

<Param name={"ephemeral"} type={"boolean"} defaultValue={"false"}>

Request a short-lived ephemeral VM. Only allowed on ephemeral-eligible plans. On those plans the VM is ephemeral whatever you send. Ignored when `snapshot_uid` is set.

</Param>

<Param name={"snapshot_uid"} type={"string"}>

UID of an `available` snapshot in this workspace to create the VM from. When set, `image_slug` is not needed.

</Param>

<Param name={"startup_script"} type={"string"}>

Optional shell script to run on the VM's first boot.

</Param>
