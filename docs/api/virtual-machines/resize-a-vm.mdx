<Endpoint method={"POST"} path={"/v1/vms/{uid}/resize"} />

Moves the VM to a different compute plan. Billing switches to the new plan's rate right
away (usage so far is settled at the old rate first).

- A **running** VM is restarted so the new CPU and memory take effect. It shows
  `provisioning` until it is back.
- A **stopped** VM gets the new resources on its next start.
- The root disk can only grow. Moving to a plan with a larger included disk expands it.
  Plans whose included disk is smaller than the VM's current disk are rejected.
- Ephemeral VMs can only move between ephemeral-eligible plans, and persistent VMs between
  persistent plans.
- VMs on a desktop image need a plan with at least 2 vCPU and 2048 MiB of memory.

The VM must be `running` or `stopped`. This is asynchronous. It returns `202 Accepted` with
an `operation_id`. See [Get an operation](/api/operations/get-an-operation). Send an
`X-Idempotency` key to make retries safe: a retry with the same key returns the original
operation with `200`, even after the resize has finished. The same key with a different
`plan_slug` returns `409` with `action: idempotency_key_reused`.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional unique key for this request, such as a UUID. Leading and trailing spaces are
ignored. If you send a key you already used for the same action on the same resource, the
original operation is returned with `200 OK` and `X-Idempotency-Replay: true`, and nothing
new is queued. The replay check runs before the resource is loaded or its state is
checked, so a retry gets the original result even after the action has finished. Reusing a
key for a different action, resource type or resource returns `409` with
`action: idempotency_key_reused`. Keys are shared across the workspace. Without a key,
every request is treated as new.

</Param>

## Request body

<Param name={"plan_slug"} type={"string"} required>

Slug of the available compute plan to move to. Case-insensitive. Must differ from the current plan.

</Param>
