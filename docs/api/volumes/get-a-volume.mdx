<Endpoint method={"GET"} path={"/v1/volumes/{uid}"} />

Returns one volume, including the VM it is attached to and its latest reported disk usage.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

The volume's `uid`.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

Lifecycle state. `available` volumes can be attached, `in-use` volumes are attached to
the VM in `vm_uid`. `failed` means creating or deleting the volume failed. See
`last_failure`. `deleted` only appears in an idempotent replay of a delete.

<Param name={"vm_uid"} type={"string"}>

Filesystem usage reported by the VM's guest agent. Omitted until the agent has reported a sample for the mounted volume. The last sample is kept after the volume is detached.

## Errors

| Status | Meaning |
|---|---|
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | No volume with this `uid` exists in the workspace, or it has been deleted. |

Errors use the [standard error format](/api#errors).
