<Endpoint method={"POST"} path={"/v1/apps"} />

Installs an app from a template. The app and all of its component deployments are created
at once and every component starts in parallel. The app's `status` moves from
`provisioning_database` (templates with backing services) or `provisioning_app` to
`active` once every component is ready, and `public_url` is then set.

If a component fails, the app becomes `failed` with the reason in `last_failure`, and the
components that were started are deleted, including their volumes, so nothing keeps
billing.

This is asynchronous. It returns `202 Accepted` with the `operation_id` of the
`app_provision` operation, which is `running` from the start. Follow it with
[Get an operation](/api/operations/get-an-operation) or poll
[Get an app](/api/apps/get-an-app).

Things to know:

- You must accept the acceptable use policy first. Until then this endpoint returns `428`
  with `action: accept_acceptable_use_policy`.
- Each component is billed as its own deployment, plus its volume. Apps cannot use the
  Free plan, because they must stay always on.
- Component deployments are named after the app, with the template's suffix for backing
  services (for example `blog` and `blog-db`).
- Open the app soon after it is live and follow `setup_note`: many apps let the first
  visitor create the admin account.
- Send `X-Idempotency` to make retries safe. Repeating a create with the same key returns
  the original `app_provision` operation with `200 OK` and `is_replay: true`, and no second
  app is created. The key is checked before anything else, including the past-due check.
  Reusing it for a different action returns `409` with `action: idempotency_key_reused`.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional key that makes retries safe. Repeating a request with a key already used for
the same action returns the original result with `200 OK` and `is_replay: true`. Reusing
it for a different action or app returns `409` with `action: idempotency_key_reused`.

</Param>

## Request body

<Param name={"template"} type={"string"} required>

Slug of an enabled template from [List app templates](/api/apps/list-app-templates). Case-insensitive.

</Param>

<Param name={"name"} type={"string"} required>

Name of the app. Leading and trailing spaces are trimmed. The slug is derived from it, with a short suffix added if it is taken in the workspace.

</Param>

<Param name={"plan_slug"} type={"string"}>

Plan for the `web` component (and for any component without a pinned plan), from [List deployment plans](/api/deployments/list-deployment-plans). Defaults to the template's `default_plan_slug`. Free plans are rejected.

</Param>

<Param name={"db_plan_slug"} type={"string"}>

Plan for the primary database component (suffix `db`). Defaults to the template's `db_default_plan_slug`. Other backing services always use their pinned plan.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `400` | Validation failed: `invalid request` (malformed JSON, or `template` or `name` missing), `unknown app template`, `name is required`, `invalid deployment plan`, `deployment plan is not available`, or `one-click apps cannot use the Free plan; choose Tiny or a larger plan so the app stays always on`. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `402` | The account is past due, so new paid resources cannot be created. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `409` | The `X-Idempotency` key was already used for a different action or a different app. Send a new key. |
| `428` | You have not accepted the acceptable use policy yet. |

Errors use the [standard error format](/api#errors).
