<Endpoint method={"GET"} path={"/v1/kubernetes/clusters"} />

Returns the workspace's Kubernetes clusters, newest first, with their nodes. Deleted clusters
are not included. This endpoint is not paginated.

The list never includes `kubeconfig` (and does not set `kubeconfig_restricted`). Use
[Get a cluster](/api/kubernetes/get-a-cluster) to read it.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

</Param>

<Param name={"status"} type={"string"} required enumValues={["provisioning","running","stopped","failed","deleting","deleted"]}>

Lifecycle state. `failed` means provisioning or a later action failed. See
`last_failure`. `deleted` is only seen on [Get a cluster](/api/kubernetes/get-a-cluster)
and in idempotent replays.

`stopped` means the platform powered off every node because the account was suspended
for non-payment. A `running` cluster switches to `stopped` (and its nodes to `stopped`,
which ends node billing) as soon as the stop is queued, and stays stopped while the
account is suspended. Within about a minute of the account becoming active again it is
restarted: it goes through `provisioning` back to `running`, or to `failed` if the
restart fails. If the stop itself fails, the cluster goes back to `running` and the stop
is retried. A stopped cluster can still be deleted.

</Param>
