<Endpoint method={"PUT"} path={"/v1/deployments/{uid}/env-vars"} />

Creates the variable, or replaces its value if a variable with the same `key` exists. The
value is stored encrypted. Every variable is available both at build time and at runtime.

Changes are staged: the running app keeps its old environment until the next deploy, and
[Get a deployment](/api/deployments/get-a-deployment) reports `env_changes_pending: true`
until then. Apply them with [Deploy a deployment](/api/deployments/deploy-a-deployment).

Requires a workspace role that can manage secrets.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Path parameters

<Param name={"uid"} type={"string"} required>

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

## Request body

<Param name={"key"} type={"string"} required>

Variable name. Starts with a letter or underscore, then letters, digits and underscores, up to 128 characters.

</Param>

<Param name={"value"} type={"string"} required>

Variable value. Must not be empty. Trailing newlines are removed (surrounding whitespace is trimmed for `env_vars` on create).

</Param>

<Param name={"scope"} type={"string"} enumValues={["build","runtime","both"]}>

Kept for older clients. Every variable is available at build time and at runtime whatever you send, and it is stored as `build`.

</Param>

<Param name={"is_secret"} type={"boolean"} defaultValue={"true"}>

Marks the value as secret.

</Param>
