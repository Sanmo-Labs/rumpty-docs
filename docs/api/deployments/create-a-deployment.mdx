<Endpoint method={"POST"} path={"/v1/deployments"} />

Creates a deployment from a Git repository.

- With `deploy_now: true`, the first build is queued straight away. The response is
  `202 Accepted` with an `operation_id` and the new `run`. Follow it with
  [Get an operation](/api/operations/get-an-operation) or
  [Get a deployment run](/api/deployments/get-a-deployment-run).
- Otherwise the deployment is only saved and the response is `201 Created` without an
  `operation_id`. Start the first build later with
  [Deploy a deployment](/api/deployments/deploy-a-deployment).

Things to know:

- You must accept the acceptable use policy first. Until then this endpoint returns `428`
  with `action: accept_acceptable_use_policy`.
- The deployment gets a unique HTTPS hostname on the platform domain, shown in `public_url`
  and `default_public_url`. The slug is derived from `name`; if it is taken in the
  workspace, a short suffix is added.
- Private repositories need the RumptyCloud GitHub App. Send `git_provider: github_app`
  and `git_repo_full_name`. If GitHub is not connected, a `deploy_now` request fails with
  `Connect GitHub before deploying this repository.`
- For GitHub App repositories, a non-empty `root_directory` is checked against the branch
  and rejected if the folder does not exist.
- On a Free plan (`free_allowance_count` above `0`), scale-to-zero is forced on, the app
  runs a single replica, and the account's Free allowance must not be used up.
- A persistent volume pins the app to one replica. Preview apps need `git_provider` and no
  volume; otherwise `preview_apps_enabled` is silently turned off.
- `env_vars` are stored encrypted and are available both at build time and at runtime.
  `build_env` values are only passed to this first build and are not stored.
- `X-Idempotency` only deduplicates creates with `deploy_now: true`, where the key is
  stored on the build operation. The same key with a different `name` returns `409`
  (`action: idempotency_key_reused`). Without `deploy_now` nothing records the key, so a
  retry creates a second deployment (with a suffixed slug).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional key that makes retries safe. Repeating a request with a key already used for
the same action on the same deployment returns the original operation with `200 OK` and
`is_replay: true` instead of queuing it again. Reusing it for a different action or
deployment returns `409` with `action: idempotency_key_reused`.
