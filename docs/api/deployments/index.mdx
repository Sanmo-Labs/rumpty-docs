Deployments build and run your application from a Git repository. Point a deployment at a
repository and branch, pick a plan, and RumptyCloud builds a container image (with Railpack or
your Dockerfile), runs it, and serves it over HTTPS on a `rumptycloud.app` hostname. You can
add custom domains, environment variables, a persistent volume, scale-to-zero and
autoscaling.

Every build or rollout is a **run**. Runs keep their build logs and, while the image is
retained, can be redeployed later to roll back.

Builds, rollouts, restarts, plan changes and deletion are asynchronous. They return
`202 Accepted` with an `operation_id`. Poll [Get an operation](/api/operations/get-an-operation)
to follow one.

Send an optional `X-Idempotency` header to make retries safe. The key is looked up before
anything else is checked, so a retry gets the original result even if the first request
already changed the deployment (for example, deleted it). If the key was already used for
the same action, the original operation is returned with `200 OK`, `is_replay: true` and
an `X-Idempotency-Replay: true` header, and nothing new is queued. If the original
operation has finished, `is_completed` is `true` and `X-Idempotency-Completed: true` is
set. Reusing a key for a different action or a different deployment returns `409` with
`action: idempotency_key_reused`. Keys are scoped to the workspace owner's account and
the workspace. Requests that queue no operation (create without `deploy_now`, a plan
change with nothing live) do not record the key, so repeating one runs it again.

If the account is suspended for non-payment, live apps are paused (`status: paused`) and
builds, rollouts, restarts, environment applies and plan changes are rejected with `402`
and `action: past_due` (as they are while the account is past due). Git pushes no longer
trigger auto-deploys and pull requests no longer get previews. Once the
account is active again, apps that suspension paused are resumed automatically within
about a minute.
