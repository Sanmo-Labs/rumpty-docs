<Endpoint method={"GET"} path={"/v1/deployments"} />

Returns the workspace's deployments, newest first. Deleted deployments, pull request
previews and the component deployments of one-click [apps](/api/apps/list-apps) are not
included. Each item carries the status of its latest run in `last_run_status`, and
`display_status` shows `updating` while a new version builds for a live app.

Without query parameters, every deployment is returned in `data`. Send `page` or
`page_size` to paginate. A top-level `pagination` object is then added next to `data`, and
`q` filters the results. `q` is ignored unless `page` or `page_size` is present.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Query parameters

<Param name={"page"} type={"integer"} constraints={"min 1"}>

Page number, starting at 1. Values below 1 (or non-numbers) are treated as `1`. Sending this enables pagination.

</Param>

<Param name={"page_size"} type={"integer"} defaultValue={"10"} constraints={"min 1 · max 100"}>

Items per page. Defaults to `10`. Values above `100` are capped at `100`. Sending this enables pagination.

</Param>

<Param name={"q"} type={"string"}>

Case-insensitive substring search across name, slug, repository URL, branch, plan slug and status. Only applied when paginating.

</Param>

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>
