<Endpoint method={"POST"} path={"/v1/databases/{uid}/snapshots/{snapshot_uid}/restore"} />

Replaces the database's data with the contents of one of its snapshots and returns
`202 Accepted`. **Everything written since the snapshot is lost.**

The snapshot must belong to this database and be `available`, and the database must use
the container runtime. During the restore the database is `provisioning` and the snapshot
is `restoring`. When the operation succeeds the database is `ready` again. If it fails,
the database is marked `failed`. Follow it with
[Get an operation](/api/operations/get-an-operation).

To restore into a new database instead, pass `snapshot_uid` to
[Create a database](/api/databases/create-a-database).

`X-Idempotency` is optional. A retry with the same key for the same snapshot returns the
original operation with `200 OK`, before the snapshot's state is checked.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

<Param name={"X-Idempotency"} type={"string"}>

Optional unique key for this request, such as a UUID. Leading and trailing spaces are
trimmed. If you send a key you already used for the same action on the same resource, the
original operation is returned with `200 OK`, `is_replay: true` and the
`X-Idempotency-Replay` header, and nothing new is queued. The replay is checked before the
resource's current state, so a retry after the first request finished still gets the
original result. Reusing a key for a different action or resource returns `409` with
`action: idempotency_key_reused`. Keys are scoped to you and the workspace and shared by
every resource type. Without a key, every request queues a new operation.

</Param>

## Errors

| Status | Meaning |
|---|---|
| `400` | The database does not support snapshots (`snapshots are only supported for container-runtime databases`). |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | The database or the snapshot does not exist (`database not found`, `snapshot not found`). |
| `409` | The snapshot is not `available` (`snapshot is not in available state for restore`), or the `X-Idempotency` key was used for a different operation (`action: idempotency_key_reused`). |

Errors use the [standard error format](/api#errors).
